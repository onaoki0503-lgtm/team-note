# 寮運営ダッシュボードと月次報告書

> **最終更新日**: 2026-10-29
> **更新者**: AI (Codex)

西松地所・寮母向けの運営入口と、提出された月次報告書の閲覧機能。入口は`?view=management`。業務ナビから月次報告、破損対応・布団入替・研修管理の準備内容を確認する。月次画面は月選択・提出者一覧・全文閲覧を維持し、日々の未提出ログを月次提出として表示しない。

## 2026-10-29：業務を追加できる入口

`?view=management`は運営ダッシュボード。既存の月次閲覧は`&section=monthly`で継続。破損・布団入替・研修は準備中の業務フローと確認事項のみを表示し、登録・承認・QR・通知や架空の件数は提供しない。概要の件数は既存RPCで得た当月の提出済み件数だけ。対象者名簿なしに未提出人数を推定しない。

業務定義は`operations.ts`へ集約、画面は`OperationsDashboard.tsx`。業務追加時は専用の画面・取得処理・サーバー側権限を接続する。カタログの利用可能フラグは認可の根拠にしない。月次文書の全文閲覧と運営業務の状態編集は分離する。実装方針と受入条件は`../../docs/DORM_OPERATIONS.md`。

- `operations.ts` — 業務カタログとURLからの選択
- `OperationsDashboard.tsx` — 運営入口・提出件数・準備中業務の流れ

## 保存と認可

Web／Flutterの既存西松地所レポートに「管理側に提出」を追加。提出時点の全文とサーバー側プロフィールを `teamnote_private.monthly_reports` に保存する。一人・一月・一寮に一件。同月の再提出では同じIDの内容を更新する。日々の業務ログは変更しない。既存の日常報告やメール送信分を勝手に月次提出へ変換しない。

`tn_submit_monthly_report` は有効な寮生だけ実行でき、著者IDはauth.uid()から決定する。管理一覧は `tn_management_monthly_reports`。毎回専用許可リストを確認する。プロフィール役職・user_metadataは認可に使用しない。新テーブルは非公開スキーマ＋RLS＋直接の利用権限なし。本文は文字として表示する。画面表示中は60秒ごととウィンドウ復帰時に一覧を再取得する。

管理者のメールは代表の回答どおり後で登録。現時点で実アカウントに管理権限を付与していない。確認済みAuthユーザーをプロジェクト管理者が `teamnote_private.management_reviewers` へ登録し、利用停止時はactive=falseにする。アプリから自己登録するAPIはない。
